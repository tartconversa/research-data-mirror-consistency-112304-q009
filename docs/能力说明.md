# 能力说明：跨区域数据产品目录、镜像接续与按范围可用性查询

本能力面向科研算力网络：不同地区的研究团队共享数据与设备资源，数据平台维护
**源端数据集 → 区域镜像 → 消费者可见目录** 三层状态。核心原则是：目录中的
可用性必须反映真实的数据版本、完整性和访问范围，**复制延迟、回报冲突或权限
不一致一律不得解释为数据已就绪**。

全部能力基于 `data/` 下的本地合成资料与标准库实现，无外部服务依赖。

## 角色与职责

| 角色 | 职责 | 对应能力 |
| --- | --- | --- |
| 数据所有者 | 批准共享范围（`share_scope`）、执行撤回与重新发布 | `withdraw_dataset` / `withdraw_partition` / `republish` |
| 复制平台主管 | 管理分区复制与完整性，核对矛盾回报、执行接续计划 | `continuation_plan` / `reconcile_reports` / `apply_task_report` |
| 区域数据管理员 | 确认区域现行访问策略版本 | `rules.REGION_CURRENT_POLICY`（R1→POL-1、R2→POL-2、R3→POL-3） |
| 消费者 | 据目录选择可用镜像，凭快照读取 | `catalog_entries` / `availability` / `open_snapshot` |

## 镜像回报折叠（mirror.fold_replicas）

镜像任务按数据产品（数据集）与分区执行，可能部分成功、重试或因源端修订而
过期。同一逻辑副本（数据集 × 区域 × 分区）可能有多条任务回报：

- 回报按 `completed_at` 升序折叠，**最新回报为准**；
- 只比较**同一目标版本**的回报：源端修订后新一轮复制携带新的元数据/策略
  版本属正常演进，不构成冲突；
- 同一目标版本的多条回报若在任务状态、校验状态、元数据版本或策略版本上
  不一致，则记为**回报冲突**，未经主管核对不得进入目录；
- 主管通过 `reconcile_reports` 核对后，以最新回报为准重新评估。

## 就绪判定（mirror.evaluate_replica）

按优先级取首个命中状态作为主状态，全部命中原因以中文列出：

| 优先级 | 状态 | 含义 |
| ---: | --- | --- |
| 1 | `release-withdrawn` | 数据集已被所有者撤回，任何镜像不得显示为可用 |
| 2 | `release-unpublished` | 数据集未发布（审核中），不进入可用目录 |
| 3 | `source-withdrawn` | 源端分区已撤回，镜像必须同步下线 |
| 4 | `source-stale` | 源端分区已被新修订取代，镜像过期 |
| 5 | `orphan-partition` | 镜像对应的源端分区不存在 |
| 6 | `report-conflict` | 同一副本回报互相矛盾，待主管核对 |
| 7 | `incomplete` | 复制未完成（排队/失败） |
| 8 | `integrity-failed` | 校验和与源端不一致 |
| 9 | `metadata-missing` | 只复制了对象，元数据（含撤回状态）未随附 |
| 10 | `policy-missing` | 访问策略未随附（POL-0） |
| 11 | `policy-stale` | 策略版本落后于区域现行版本，权限不一致 |
| 12 | `version-lag` | 副本版本落后于源端当前修订（复制延迟） |
| 13 | `ready` | 就绪 |

只复制对象而未复制元数据或撤回状态会造成不一致，因此 `META-0`/`POL-0`/
`missing-meta` 与策略版本滞后都直接判为不就绪。

## 目录条目（catalog.CatalogEntry）

每个（数据集 × 区域）条目向消费者展示：

- `replica_versions`：各分区的副本版本；
- `covered_partitions` / `pending_partitions`：覆盖分区与未就绪分区（附原因）；
- `last_consistent_at`：**最后一致时间**，取全部就绪分区一致时间的最小值；
- `access_owner` / `access_other`：本地访问许可（见下）；
- `status`：`available` / `partial` / `building` / `inconsistent` / `stale` /
  `withdrawn` / `unpublished`。

## 按范围可用性查询（catalog.availability）

请求范围（与 `consumer_requests.csv` 的 `requested_scope` 一致）：

- `whole-release`：需要数据集全部有效源端分区在区域内就绪；
- `partition-only`：仅要求指定分区就绪（分区不存在则拒绝）；
- `analysis`：覆盖要求同 whole-release，且快照额外固定访问策略版本以便审计。

本地访问许可矩阵（`share_scope` × 敏感级别 × 消费者身份）：

| 共享范围 | 消费者 | open | controlled | restricted |
| --- | --- | --- | --- | --- |
| `none` | 任意 | 拒绝 | 拒绝 | 拒绝 |
| `project` | 所有者实验室 | 允许 | 需审批 | 需审批 |
| `project` | 其他实验室 | 需审批 | 需审批 | 拒绝 |
| `consortium` | 任意联盟成员 | 允许 | 需审批 | 拒绝（所有者需审批） |

最终决定 = 数据可用性（全部/部分/无就绪分区）与访问许可（允许/需审批/
拒绝）的保守合成：任一维度为拒绝则 `deny`，任一维度为部分/需审批则
`partial`，否则 `allow`。`allow`/`partial` 时答复随附**快照锚点**
（`SnapshotPin`：分区版本、策略版本、最后一致时间），供开启读取快照。

## 镜像接续计划（mirror.plan_continuation）

对未就绪副本生成接续动作，按优先级排序：

| 优先级 | 动作 | 触发 |
| ---: | --- | --- |
| 0 | `propagate-withdrawal` | 源端撤回：下线并墓碑化区域副本，停止重试 |
| 1 | `resolve-conflict` | 回报矛盾：主管核对 |
| 2 | `repair-integrity` | 校验未通过：重新传输（attempt+1） |
| 3 | `sync-metadata` | 补同步元数据与撤回状态 |
| 4 | `sync-policy` | 按区域现行策略重同步 |
| 5 | `refresh-source` | 源端已修订：按当前版本重新镜像（attempt+1） |
| 6 | `retry-copy` | 失败重试（attempt+1） |
| 7 | `resume-copy` | 排队任务继续 |

未发布（审核中）的数据集不产生平台动作，等待数据所有者发布。接续动作的
执行结果通过 `apply_task_report` 回报，平台重新折叠评估，形成闭环。

## 读取快照与撤回影响（snapshots）

- 消费者凭可用性答复开启快照租约（`open_snapshot`），快照固定分区版本、
  策略版本与一致时间；`deny` 答复不能开启快照；
- 源端撤回或重新发布后，**已开始的读取保留其快照身份**，可凭快照完成；
  租约附加中文影响说明（撤回后不得开启新读取、不得用于新分析或再分发；
  重新发布后快照不再代表最新可用），且 `current=False`；
- 旧镜像在撤回/重发布后立即从目录可用状态中移除，不得继续显示为最新可用；
- `consumer_requests.csv` 中的历史请求登记为历史快照租约（30 个
  `snapshot_ref`），撤回事件同样向其传播影响说明。

## 合成资料画像（python3 examples/demo_catalog.py 可复现）

对 `data/` 合成资料构建目录的结果：

- 42 个目录条目：14 `withdrawn`（数据集已撤回）、14 `unpublished`
  （审核中）、14 `stale`（源端分区已被新修订取代）；**无一可用**——
  合成资料中每个逻辑副本的策略版本回报均互相矛盾，且撤回/过期状态普遍，
  平台拒绝把任何副本解释为就绪；
- 接续计划：14 条 `propagate-withdrawal`（优先级 0）+ 14 条
  `refresh-source`（优先级 5）；审核中的数据集不产生动作；
- 30 个历史快照租约；撤回事件会向受影响租约附加影响说明。

正向路径（就绪 → 快照 → 撤回 → 重发布 → 重新镜像 → 恢复可用）由
`tests/` 下的合成场景测试覆盖。

## 运行

```sh
python3 -m unittest discover -s tests -v   # 58 个合成测试
python3 examples/demo_catalog.py           # 目录/查询/接续/撤回演示
```

## 模块地图

| 模块 | 职责 |
| --- | --- |
| `rules.py` | 枚举、区域现行策略常量、版本/时间工具 |
| `records.py` | CSV 记录与加载（不附加结论） |
| `mirror.py` | 回报折叠、就绪评估、接续计划 |
| `catalog.py` | 目录条目、许可矩阵、按范围可用性查询 |
| `snapshots.py` | 快照锚点/租约、撤回与重发布影响 |
| `service.py` | 一体化门面：查询、快照、生命周期事件 |
